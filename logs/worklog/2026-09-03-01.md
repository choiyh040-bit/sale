## 왜 이렇게 했나
<!-- 다른 선택지가 있었다면 왜 그걸 안 골랐는지. 3개월 뒤의 내가 읽습니다. -->

**기본 모델을 최신(`gemini-3.8-flash`)이 아니라 `gemini-3.5-flash` 로 내린 이유.**
최신이 좋아 보여서 3.8 로 잡았는데 큰 요청에서 503 이 계속 났다. 같은 요청이 3.5 에서는
멀쩡히 돌아간다. 무료 등급에서는 최신 모델일수록 붐빈다. **돌아가는 게 최신보다 낫다.**

**폴백을 넣은 이유.** 모델 하나에 매달리면 그 모델이 붐비는 날엔 아무것도 못 만든다.
503(붐빔)·429(호출 과다)만 골라서 재시도하고, 그래도 안 되면 다음 모델로 넘어가게 했다.
모델명 오류(404)나 키 오류는 재시도해도 소용없으므로 바로 올려보낸다 — 여기서 재시도하면
사용자가 원인을 못 보고 30초를 기다리게 된다.

**모델명을 코드에 박지 않고 환경변수(`GEMINI_MODEL`)로 뺀 이유.** 오늘 하루에만
2.5 → 3.8 → 3.5 로 두 번 갈아탔다. 모델명은 계속 늙는다는 게 확인됐으므로 바깥에서
바꿀 수 있어야 한다.



## 막힌 점 / 배운 점
<!-- 에러 메시지 원문, 삽질한 시간, 해결한 방법. 여기가 이 일지에서 제일 값어치 있는 칸입니다. -->

**1. `gemini-2.5-flash` 가 404 로 죽어 있었다.**
```
404 NOT_FOUND. This model models/gemini-2.5-flash is no longer available to new users.
Please update your code to use models/gemini-3.6-flash
```
모델 목록에는 **이름이 그대로 보이는데** 신규 사용자만 못 쓴다. 목록에 있다고 쓸 수 있는 게
아니다. 55개를 뽑아 확인했다.

**2. `gemini-3.8-flash` 의 503 — 여기서 제일 오래 헤맸다.**
```
503 UNAVAILABLE. This model is currently experiencing high demand.
```
"일시적"이라기에 4번 재시도했는데 전부 실패. **평문 인사는 되고 `make_toon` 만 실패**해서
스키마를 의심하고 조각별로 이분 탐색했다(plan/character/cuts/caption/hashtags, enum 제거).
`caption` 하나짜리 최소 스키마도 실패하길래 스키마 모양 문제가 아님을 알았고,
같은 요청을 다른 모델에 던져보니 3.5·3.1-lite 는 정상 → **모델 용량 문제로 확정.**
→ 배운 것: **503 은 "기다리면 낫는다"가 아니라 "이 모델은 지금 이 크기를 못 받는다"** 일 수 있다.
갈라서 확인할 것 — 평문 vs 구조화, 이 모델 vs 다른 모델.

**3. 진단하다가 429 를 밟았다.**
```
429 RESOURCE_EXHAUSTED
```
연속 6회 호출로 분당 제한에 걸렸다. 잠깐 뒤엔 다시 됐다. **무료 등급은 폭주하면 막힌다.**
디버깅할 때도 `sleep` 을 끼울 것. 이걸 할당량 소진으로 잘못 읽을 뻔했다.
